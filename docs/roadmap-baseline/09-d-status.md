## Findings

- **D01 Identity/account.** Network is a real OAuth2/OIDC IdP; Live keeps its own users table and Community translates identity through Live.
- **D02-D04 Registry, capabilities, contracts.** Three partial registries (url_registry, Tools catalog, Sites catalog); contracts are prose in CONTRACTS.md; no capability layer.
- **D05-D06 Policy, staff, user modules.** Roles and admin exist per service; no shared capability map; versioned user modules do not exist.
- **D07-D10 Themes, notifications, social, analytics.** Themes and notifications are shared and real; follows exist in both Live and Network; analytics is per site with no retention.
- **D11-D13 Events, realtime, SDK.** Cross-service effects are direct internal POSTs and HMAC webhooks; every realtime channel is a product-local WebSocket server; no SDK.
- **D14-D16 Media.** Real service with B2/R2 tiering; predecessor-shaped vods/clips/files tables, still owns paste semantics.
- **D17-D20 Live, OpenRe, channel/VOD lineage.** Live owns RTMP/WHIP/WebRTC ingest and restream in-process.
- **D21-D23 Chat.** Rooms, DMs, TTS, soundboard, calls and moderation work, all as a Live module.
- **D24-D27 Community.** SSR paste pages only; no database; comments live in Live, paste semantics in Media and (frozen) Live.
- **D28-D30 Billing, Tips, VIP.** Money split across Network (OpenCoins wallet) and Live (Vibes/PayPal, subscriptions); no ledger authority or reconciliation.
- **D31 Tools.** Gateway plus 7 satellites running; shared jobs/media primitives absent.
- **D32 Games.** Authoritative world with Network SSO; not on shared chrome, no mod platform.
- **D33-D34 Codes, Host.** Charter repositories only.
- **D35-D38 AI, content, sources, search.** Large AI subsystem inside Live; no source registry, search index or publishing runtime.
- **D39 Mods.** No mod manifest, grants or sandbox in the platform (Source.OpenVibe.Games has its own runtime, not audited here).
- **D40 Open developer services.** Only a first-party PowerChat integration; internal calls use shared loopback keys.
- **D41 Independent runtime lifecycle.** Repos deploy independently and Live is socket-activated, but Live restarts drop RTMP and Media restarts orphan recordings.
- **D42 Shared component architecture.** openvibe-shared is vendored by copy; consumers can drift from canonical.
- **D43 Safe active-client updates.** Live has a deploy notice and content-hashed assets; no release manifests or update coordinator.
- **D44 Crawlable component rendering.** SSR/static with metadata in Network, Tools, Media, Community and Sites.
- **D45 Release compatibility and recovery.** Deploy is git pull + restart; no versioned releases or mixed-version policy.
- **D46 Update observability and acceptance.** No CI outside AFResume; no release telemetry.
